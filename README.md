# GenHub

Личный агрегатор нейрогенерации видео и изображений. Запросы идут напрямую в API провайдеров (BytePlus ModelArk для Seedance, fal.ai для остальных моделей), а стоимость каждой генерации видна сразу.

Пользователь один, вход по одному паролю.

## Стек

- Next.js 16 (App Router) + TypeScript, Tailwind
- SQLite (better-sqlite3) + Drizzle ORM, миграции в `drizzle/`
- Файлы результатов на локальном диске в `DATA_DIR`
- Фоновая обработка задач в том же процессе (см. ниже)

## Быстрый старт

Нужен Node.js 22+.

```bash
npm install
cp .env.example .env      # задайте APP_PASSWORD
npm run dev               # http://localhost:3000
```

Миграции применяются автоматически при старте сервера. Применить их вручную:

```bash
npm run db:migrate
```

Продакшен-сборка локально:

```bash
npm run build
npm start
```

> При `npm start` (`NODE_ENV=production`) cookie сессии ставится с флагом `Secure`. На `localhost` браузеры это допускают. Если открываете сервер по голому `http://IP`, задайте `COOKIE_SECURE=false`. За Caddy с HTTPS (этап 7) ничего менять не нужно.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `APP_PASSWORD` | Пароль входа. Без него вход невозможен. |
| `SESSION_SECRET` | Ключ подписи cookie. Если пусто, выводится из пароля, поэтому смена пароля разлогинивает все сессии. |
| `DATA_DIR` | Каталог для БД (`app.db`) и файлов результатов. По умолчанию `./data`. |
| `PROVIDER_MODE` | `mock` (без сети, тестовые результаты) или `real`. |
| `FAL_KEY`, `BYTEPLUS_API_KEY` | Ключи провайдеров, нужны только в режиме `real`. |
| `APP_TIMEZONE` | Часовой пояс для границ месяца в расходах. По умолчанию `Europe/Kyiv`. |
| `MONTHLY_BUDGET_USD` | Месячный лимит расходов. Пусто означает без лимита. |
| `MAX_CONCURRENT_JOBS` | Сколько генераций одновременно у провайдеров. По умолчанию 5. |
| `WORKER_INTERVAL_MS` | Как часто фоновый цикл проверяет задачи. По умолчанию 2000. |
| `MOCK_MIN_MS`, `MOCK_MAX_MS` | Сколько длится mock-генерация. По умолчанию 5–15 с. |

Секреты хранятся только в `.env`, а он в `.gitignore`.

## Как обрабатываются задачи

1. Форма отправляет `POST /api/jobs`. Параметры проверяются по схеме модели, считается оценка стоимости, задача пишется в БД со статусом `queued`.
2. Фоновый цикл (`src/worker`) запускается вместе с сервером из `instrumentation.ts` и каждые 2 секунды:
   - опрашивает провайдера по задачам `running`; при `done` или `failed` записывает результат или текст ошибки;
   - отправляет задачи из `queued` провайдеру, но не больше `MAX_CONCURRENT_JOBS` одновременно.
3. Страницы «Генерация» и «История» опрашивают `GET /api/jobs`, пока есть незавершённые задачи.

Цикл работает в том же процессе, что и Next.js, поэтому у приложения один контейнер, а у SQLite один писатель. Всё состояние хранится в БД: после перезапуска задачи `running` продолжают опрашиваться по `provider_job_id`. Если сервер упал между взятием задачи и отправкой провайдеру, задача помечается `failed`, а не отправляется повторно, чтобы не заплатить дважды.

### Адаптеры провайдеров

Интерфейс описан в `src/providers/types.ts`:

- `generate(model, { prompt, params })` возвращает `providerJobId`;
- `getStatus(model, providerJobId)` возвращает `queued | running | done (+resultUrl) | failed (+error)`.

Новый провайдер добавляется одним файлом в `src/providers/` и регистрируется в `src/providers/index.ts`. При `PROVIDER_MODE=mock` все модели идут в mock-адаптер.

Mock-адаптер не ходит в сеть. Если в промпте есть слово `fail`, генерация завершится тестовой ошибкой.

### Каталог моделей

Модели хранятся в таблице `models`: провайдер, цена, единица цены, схема параметров формы. Начальный каталог лежит в `src/db/seed.ts` и добавляется только при отсутствии записей, поэтому цены, исправленные в БД, при перезапуске не затираются.

## Структура

```
src/
  app/            страницы и API (App Router)
  db/             схема Drizzle и подключение к SQLite
  lib/            конфиг, авторизация, параметры, цены, задачи
  providers/      адаптеры провайдеров (mock, позже fal и BytePlus)
  worker/         фоновый цикл обработки задач
  components/     UI-компоненты
  proxy.ts        проверка сессии на каждом запросе (в Next 16 бывший middleware)
  instrumentation.ts  код при старте сервера: миграции и запуск фонового цикла
drizzle/          SQL-миграции
tests/            тесты
```
