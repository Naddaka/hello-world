# GenHub

Личный агрегатор нейрогенерации видео и изображений. Запросы идут напрямую в API провайдеров (BytePlus ModelArk для Seedance, fal.ai для остальных моделей), а стоимость каждой генерации видна сразу.

Пользователь один, вход по одному паролю.

## Стек

- Next.js 16 (App Router) + TypeScript, Tailwind
- SQLite (better-sqlite3) + Drizzle ORM, миграции в `drizzle/`
- Файлы результатов на локальном диске в `DATA_DIR`
- Фоновая обработка задач в том же процессе (см. ниже)

## Быстрый старт

Нужен Node.js 22+.

```bash
npm install
cp .env.example .env      # задайте APP_PASSWORD
npm run dev               # http://localhost:3000
```

Миграции применяются автоматически при старте сервера. Применить их вручную:

```bash
npm run db:migrate
```

Продакшен-сборка локально:

```bash
npm run build
npm start
```

> При `npm start` (`NODE_ENV=production`) cookie сессии ставится с флагом `Secure`. На `localhost` браузеры это допускают. Если открываете сервер по голому `http://IP`, задайте `COOKIE_SECURE=false`. За Caddy с HTTPS (этап 7) ничего менять не нужно.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `APP_PASSWORD` | Пароль входа. Без него вход невозможен. |
| `SESSION_SECRET` | Ключ подписи cookie. Если пусто, выводится из пароля, поэтому смена пароля разлогинивает все сессии. |
| `DATA_DIR` | Каталог для БД (`app.db`) и файлов результатов. По умолчанию `./data`. |
| `PROVIDER_MODE` | `mock` (без сети, тестовые результаты) или `real`. |
| `FAL_KEY`, `BYTEPLUS_API_KEY` | Ключи провайдеров, нужны только в режиме `real`. |
| `APP_TIMEZONE` | Часовой пояс для границ месяца в расходах. По умолчанию `Europe/Kyiv`. |
| `MONTHLY_BUDGET_USD` | Месячный лимит расходов. Пусто означает без лимита. |
| `MAX_CONCURRENT_JOBS` | Сколько генераций одновременно у провайдеров. По умолчанию 5. |
| `WORKER_INTERVAL_MS` | Как часто фоновый цикл проверяет задачи. По умолчанию 2000. |
| `MOCK_MIN_MS`, `MOCK_MAX_MS` | Сколько длится mock-генерация. По умолчанию 5–15 с. |

Секреты хранятся только в `.env`, а он в `.gitignore`.

## Как обрабатываются задачи

1. Форма отправляет `POST /api/jobs`. Параметры проверяются по схеме модели, считается оценка стоимости, задача пишется в БД со статусом `queued`.
2. Фоновый цикл (`src/worker`) запускается вместе с сервером из `instrumentation.ts` и каждые 2 секунды:
   - опрашивает провайдера по задачам `running`; при `done` или `failed` записывает результат или текст ошибки;
   - отправляет задачи из `queued` провайдеру, но не больше `MAX_CONCURRENT_JOBS` одновременно.
3. Страницы «Генерация» и «История» опрашивают `GET /api/jobs`, пока есть незавершённые задачи.

Цикл работает в том же процессе, что и Next.js, поэтому у приложения один контейнер, а у SQLite один писатель. Всё состояние хранится в БД: после перезапуска задачи `running` продолжают опрашиваться по `provider_job_id`. Если сервер упал между взятием задачи и отправкой провайдеру, задача помечается `failed`, а не отправляется повторно, чтобы не заплатить дважды.

### Адаптеры провайдеров

Интерфейс описан в `src/providers/types.ts`:

- `generate(model, { prompt, params })` возвращает `providerJobId`;
- `getStatus(model, providerJobId)` возвращает `queued | running | done (+resultUrl) | failed (+error)`.

Новый провайдер добавляется одним файлом в `src/providers/` и регистрируется в `src/providers/index.ts`. При `PROVIDER_MODE=mock` все модели идут в mock-адаптер.

Mock-адаптер не ходит в сеть. Если в промпте есть слово `fail`, генерация завершится тестовой ошибкой.

### Хранение результатов

Ссылки провайдеров быстро протухают, поэтому файл скачивается сразу, как только провайдер сообщил о готовности. Задача становится «Готово» только после того, как все её файлы сохранены.

- Файлы лежат в `DATA_DIR/results/<id задачи>/<номер>.<расширение>`. У одной задачи может быть несколько файлов, например 4 картинки. Запись идёт во временный `.part`, поэтому оборванное скачивание не оставит битый файл.
- Если скачать не удалось, попытка повторяется на следующих проходах цикла. После 5 неудач задача получает статус «Ошибка» с текстом причины, а исходные ссылки провайдера остаются в БД (`result_urls`).
- Раздача идёт через `GET /api/jobs/<id>/files/<номер>` и только с действующей сессией. Файл ищется по id задачи в БД, путь из запроса не используется. Поддерживаются Range-запросы (перемотка видео), а `?download` отдаёт файл на скачивание.
- В mock-режиме «скачиваются» тестовые файлы из `assets/mock/`.

### fal.ai

Адаптер `src/providers/fal.ts` работает через [queue API](https://fal.ai/docs/documentation/model-apis/inference/queue):

1. `POST https://queue.fal.run/<endpoint id>` ставит запрос в очередь.
2. `GET status_url` возвращает статус: `IN_QUEUE`, `IN_PROGRESS` или `COMPLETED`.
3. `GET response_url` возвращает результат.

Адреса статуса и результата берутся из ответа на submit: для составных endpoint id они отличаются от адреса отправки. Ключ отправляется только на `queue.fal.run` и нигде не логируется.

Как включить реальный режим:

```bash
PROVIDER_MODE=real
FAL_KEY=...            # https://fal.ai/dashboard/keys
```

Модели в каталоге (цены с fal.ai/models, проверены 15.10.2026):

| Модель | Endpoint | Цена |
|---|---|---|
| Kling 3.0 Pro | `fal-ai/kling-video/v3/pro/text-to-video` | $0.112/с без звука, $0.168/с со звуком |
| Veo 3.1 Fast | `fal-ai/veo3.1/fast` | $0.10/с, со звуком $0.15/с; 4K $0.30 и $0.35 |
| Nano Banana Pro | `fal-ai/nano-banana-pro` | $0.15 за изображение, 4K вдвое дороже |
| Seedream 4.5 | `fal-ai/bytedance/seedream/v4.5/text-to-image` | $0.04 за изображение |

Новая модель fal добавляется без нового кода, одной записью в `src/db/seed.ts` (или строкой в таблице `models`):

- `provider: "fal"`, `providerModelId`: endpoint id из документации модели;
- `paramsSchema`: поля формы, ключи совпадают с именами параметров API;
- цена и единица цены.

Адаптер отправляет `{ prompt, ...параметры }` и забирает файлы из полей ответа `video`, `videos`, `image` и `images`.

### BytePlus ModelArk (Seedance)

Адаптер `src/providers/byteplus.ts` использует [API видеогенерации ModelArk](https://docs.byteplus.com/en/docs/ModelArk/create-video-generation-task-api):

- `POST https://ark.ap-southeast.bytepluses.com/api/v3/contents/generations/tasks` с заголовком `Authorization: Bearer <ключ>` создаёт задачу;
- `GET .../contents/generations/tasks/{id}` возвращает статус `queued`, `running`, `succeeded`, `failed` или `expired`, ссылку `content.video_url` и `usage.completion_tokens`.

Ссылка на видео живёт 24 часа, поэтому файл скачивается сразу.

```bash
PROVIDER_MODE=real
BYTEPLUS_API_KEY=...   # консоль ModelArk, регион ap-southeast-1 → API Key management
```

Перед первым запуском модель нужно активировать в консоли ModelArk. Для Seedance 2.5 нужен баланс больше $30 или пакет ресурсов, подробности в [туториале](https://docs.byteplus.com/en/docs/ModelArk/seedance-2-5).

| Модель | id | Возможности | Цена (без видео на входе) |
|---|---|---|---|
| Seedance 2.5 | `dreamina-seedance-2-5-260628` | 4–30 с, 480p / 720p / 1080p, звук | $10.70 за 1M токенов, 1080p $11.70 |
| Seedance 2.0 Fast | `dreamina-seedance-2-0-fast-260128` | 4–15 с, 480p / 720p, звук | $5.60 за 1M токенов |

**Стоимость.** Токены оцениваются как `длительность × ширина × высота × 24 / 1024`; размеры кадра берутся из таблицы в документации и записаны в `price_rules` модели. Например, Seedance 2.5, 720p, 16:9, 5 с: 108 000 токенов, $1.16. После генерации BytePlus сообщает фактические токены, и точная стоимость сохраняется в `jobs.cost_actual`.

**Референс-изображение.** Картинка загружается в форме (PNG, JPEG или WebP, до 10 МБ) и хранится в `DATA_DIR/uploads/`. Провайдеру она уходит как `data:image/...;base64`, так что публичный URL не нужен. Есть две роли:

- «Первый кадр» (`first_frame`). Соотношение сторон тогда принудительно `adaptive`, как требует документация Seedance 2.5.
- «Референс» (`reference_image`): стиль или персонаж, соотношение сторон остаётся выбранным.

**Открытые вопросы** (помечены `TODO(byteplus)` в коде):

- требование `adaptive` для первого кадра в документации описано только для 2.5; для 2.0 Fast мы его тоже применяем;
- формат поля `error` у задачи со статусом `failed` в документации не расписан; предполагается тот же `{ code, message }`, что у HTTP-ошибок (он проверен на живом API);
- ограничения на размер картинки (300–6000 px, пропорции 0.4–2.5) проверяет сам провайдер, у нас проверяются только формат и вес файла.

### Расходы и лимит

На странице «Расходы» (`/spending`) показаны:
- итог за месяц, число успешных генераций, средняя цена генерации и сумма задач в работе;
- разбивка по моделям и по провайдерам;
- переключение месяцев стрелками.

Правила учёта (`src/lib/spending.ts`), учёт приблизительный:

- **готово**: фактическая стоимость от провайдера (BytePlus сообщает токены), иначе цена по каталогу на момент запуска;
- **ошибка**: $0, если только провайдер не сообщил о списании;
- **в очереди / генерируется**: ещё не списано, но оценка резервируется в лимите;
- месяц определяется по времени создания задачи в `APP_TIMEZONE` (по умолчанию Киев, переход на зимнее время учтён).

**Лимит.** `MONTHLY_BUDGET_USD` задаёт месячный лимит. Новая генерация блокируется, если «потрачено + в работе + оценка этой генерации» больше лимита. Форма в этом случае показывает понятное сообщение, а API отвечает `402`. Шкала лимита видна на главной и в «Расходах»: от 80% она становится жёлтой, при исчерпании красной.

**Цены без релиза.** На странице «Модели» (`/models`) можно поменять цену, правила цены (JSON) и включить или выключить модель. Новая цена влияет на новые генерации, уже созданные задачи не пересчитываются.

### Каталог моделей

Модели хранятся в таблице `models`: провайдер, цена, единица цены, схема параметров формы. Начальный каталог лежит в `src/db/seed.ts` и добавляется только при отсутствии записей, поэтому цены, исправленные в БД, при перезапуске не затираются.

## Структура

```
src/
  app/            страницы и API (App Router)
  db/             схема Drizzle и подключение к SQLite
  lib/            конфиг, авторизация, параметры, цены, задачи
  providers/      адаптеры провайдеров (mock, позже fal и BytePlus)
  worker/         фоновый цикл обработки задач
  components/     UI-компоненты
  proxy.ts        проверка сессии на каждом запросе (в Next 16 бывший middleware)
  instrumentation.ts  код при старте сервера: миграции и запуск фонового цикла
drizzle/          SQL-миграции
assets/mock/      тестовые видео и картинка для mock-режима
tests/            тесты
```
